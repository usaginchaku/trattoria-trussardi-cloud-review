0. 共通ルール
- 1試験で変えるのは1要因だけ。他はすべて対照撮影と同一。
- 保存済み RI03 シーンの「新しい診断コピー」でのみ実施。本体 UnityProject・RI01〜RI03・原本は編集も保存もしない。
- 各撮影は 1920x1080 PNG + 線形 FLOAT32 EXR。SHA256 と展開RGBA SHA を記録。終了後に状態・資源を復元し保全照合（MAT07/07C/FOLLOWUP04 と同じ手順）。
- 形状変更と材質変更を同じ試験に混ぜない。B の影板は「追加物」と表記し、料理メッシュ編集と区別する。
- NormalOff、MatCapOff、ShadowStrengthZero、Ceramic ShadowBlur1.0、FUP04 の blend/FBX は再実行しない。
- Bake/AO、Play、Build & Test、SDK、upload はどの試験にも含めない。
- 結果は試験条件についての証拠に限る。カプレーゼの結果を他料理へ一般化しない。

固定条件
- Unity 2022.3.22f1 / lilToon 2.3.4 / BRP / Linear / DX11（MAT07 記録）
- カメラ: 既存固定の FoodCaprese（主）、FoodLamb / FoodPuttanesca / FoodPudding（副）、屋外陽性対照 EntranceUpper または Sign
- 品質: VRC Medium。VRC Mobile は指定した試験だけ別記
- 光: 記録どおり13灯（Baked点光源12、Review_Sun Mixed 強度0.9 ソフト影）。既存ライトマップ/プローブは変更せず、再ベイクしない
- 露出・出力: MAT07 基準と同じカメラ/後処理設定
- 形状・材質: RI03 保存状態（POSE01 上トースト、Menu/Sign アルベド、RI02 材質）。倍率 0.7825509309768677、プリン2枚皿、Water、配置は不変

対照
- 陰性（再現性）: 変更なしの対照を2回撮影し全画素一致を確認。不一致ならその回は無効。
- 陽性（屋外）: 光の On/Off 試験では、屋外の既存実時間影（メニュー台→壁、街灯→地面）が必ず変わること。変わらなければ切替が効いていない。
- 読取専用の T1/T2 を描画試験より先に行う。

仮説（確定事項と区別）
H1 卓上では Mixed の太陽が遮られ（Shadowmask のプローブ遮蔽）、料理に実時間影を落とす光源がない。— 未確認
H2 卓上のプローブ SH は方向成分（L1）が弱く、lilToon の形の陰影に使える光の向きが乏しい。— 未確認（皿斜面の表示値 200〜201 が根拠の観察）
H3 料理/卓の Renderer の castShadows/receiveShadows や影距離が影を止めている。— 同梱記録に情報なし
H4 クロスの表示飽和が弱い接触影を隠している。— 部分的な説明に留まる可能性（プリン画角は飽和7.5%でも接触暗部なし）
H5 lilToon の陰影パラメータ — MAT07/07C で検討済み、新証拠なしに再試行しない
H6 皿の形が浅い1段で、2段の参照より形が読みにくい — 形状の別系統。今回は未承認
※ H1・H2・H3・H4 は同一原因として扱わない。

試験
T1 既存 EXR の線形値読取（変える要因なし・読取のみ）
  対象: H4。ローカルにある MAT07 基準 / POSE01 の EXR を読む。
  観察: クロス（皿直下・遠方）、皿斜面の線形RGB、1.0超の画素数。矩形は analysis_measurements.json と同じ。
  解釈: クロスが1.0を大きく超える→弱い接触影が見えなくなる余地あり、露出/トーンマップは別要因として後で計画。1.0未満→この画角で H4 は否定。
  限界: 皿が平坦な理由は分からない。1画角のみ。
  保全: 読取のみ、前後ハッシュ。承認: ローカルファイル読取の許可（プロジェクト変更なし）。

T2 料理位置のプローブ読取（変える要因なし・診断コピーで読取、保存しない）
  対象: H1/H2。Editor スクリプトで皿中心・縁・パン位置の補間プローブ（SH と遮蔽値）を取得。API 名は実行者が Unity 2022.3 公式資料で確認すること（本作業では Web を見ていない）。
  解釈: 太陽チャンネルの遮蔽 ≈0 → H1 を支持。L1 が L0 に比べ小さい → H2 を支持。遮蔽が明確に >0 → 太陽は卓に届くはず、H3 を読取で確認へ。
  限界: プローブ補間はシェーダーの画素結果ではない。lilToon が SH をどう使うかは示さない。
  承認: 診断用 Unity Editor バッチ実行（Play/Bake なし）。

T3 仮説0: Review_Sun の On/Off（変える要因: Review_Sun の Light 有効/無効のみ）
  カメラ: FoodCaprese + EntranceUpper（陽性対照）。
  観察: 皿・パン・皿周囲クロスの PNG と線形 EXR の画素差。
  解釈: 卓上の差 ≈0 かつ屋外は変化 → 卓上で太陽の実時間寄与なし（H1 と整合）。卓上も変化 → 太陽は届いている。影を落とすかは T4 へ。
  この試験だけで決められないこと: A の新光源で良い影が出るか、プローブの方向性（H2）、ベイクの必要性、差0 のとき遮蔽と Renderer 設定（H3）のどちらか。
  保全: 診断コピーで切替→復元→シーン/資源ハッシュ照合。承認: 診断 Unity 撮影（Play/Bake なし）。

T4 太陽の影だけ Off（T3 で卓上が変化した場合のみ）
  変える要因: Review_Sun の影 Soft→None のみ。
  解釈: 変化あり → 太陽の実時間影は卓に落ちている。変化なし → 光は届くが影は見えない、H3 を値を試さず設定読取で確認。

T5 選択肢A の試験: 卓上限定の実時間ライト1灯（変える要因: このライトの追加のみ）
  条件: ソフト影、カリングマスクを料理/皿/クロスの層に限定、方向は参照に近い前上方から固定。材質値は一切変えない。
  観察: 皿のくぼみ・縁の階調、パン下の接触、クロスの接触影、新たな白飛び。VRC Mobile 品質でも別記録。
  解釈: 接触影と皿の階調が新たな飽和なく読める → A は見た目選定の候補。変化が小さい → 光の経路は律速でない、H6（形）または B を再検討。
  限界: 記録上 VRC Mobile は影なし → A の影は Mobile/Quest では出ない見込み。PC 負荷・Quest は本試験で測らない。
  承認: 診断用候補ライトの作成承認。RI04 以降への採用は別承認。

T6 選択肢B の試験: 描き込み接触影の板（追加物。メッシュ編集ではない）
  変える要因: カプレーゼの皿の下とパンの下に半透明の影板を追加するだけ。料理メッシュ・材質・光は不変。
  観察: 接触の読みやすさ、透明の水グラスとの描画順・ちらつき、4料理カメラと浅い角度での見え方。
  解釈: 参照に近い接触が読める → 候補。描画順の不具合や貼り付け感 → 不採用。
  限界: 光に追従しない。皿の形の陰影は変わらない。

T7 選択肢C（今は推奨しない）: 料理 Static 化 + 再ベイク/AO
  Bake/AO は未承認。シーン全体のライトマップが変わり一要因比較にならず、料理が動かせなくなる。記載のみ。
