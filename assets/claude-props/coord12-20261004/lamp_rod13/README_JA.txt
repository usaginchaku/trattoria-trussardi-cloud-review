■ 推測にとどまること(事実としては扱わない)
- 「同じ添付が、サービス側で縮小・再符号化されたもの」かどうかは、元ファイルがないと確かめられない。
- 元ファイルの寸法と向き(EXIF の Orientation)が分からない。元が 4:3 なら、Cloud の 16:9 は切り抜きを伴うことになる。
- 写っている内容と依頼文の説明の対応:

  - 添付 2: レンガの暖炉と瓶棚、その左の壁灯。依頼の「暖炉側の瓶棚の左」と合う。
  - LAMP11 でのファイル名の割り当ては、依頼文の記載と添付の順番、この内容の対応に基づいていた。ファイルの由来を確かめた結果ではない。

■ 由来を実証するための最小の手順(ローカル、元ファイルを公開せずに数値だけ)
1. 元の 2 ファイルの寸法、EXIF の Orientation、縦横比を記録する。
2. このフォルダの tools/provenance_audit.py を元ファイルに対して実行し、aHash64 と dHash64 を出す(EXIF の向きを適用してから計算する)。
3. Cloud 側の値と比べる:
   - 添付 1: aHash 7c24242c6e6e7c3c / dHash 1716323735332b0f
   - 添付 2: aHash 007c6c7d7d7cfcbc / dHash a61626263627ab9b
   - ハミング距離が小さければ(目安 ≤ 6)、同じ写真から作られたものという強い傍証になる。
   - 元が 4:3 で切り抜きがあると、ハッシュは一致しにくい。その場合は、元を長辺 2000 px に縮めて目視で比べてもらう必要がある。
4. 結果の数値を Cloud に送ってもらえれば、腕の太さの比較(LAMP13 の後半)を再開できる。
