■ 一要因診断（実行順。すべて新しい診断コピーで、本体・RI03 は保存しない。Play・Bake なし）
D1 既存 EXR の線形値読取（変える要因なし）
  入力: MAT07 baseline / POSE01 の FoodCaprese EXR（ローカル既存）。COORD05 analysis_measurements.json と同じ矩形
  期待差: クロスが 1.0 を大きく超えるなら H4 の余地あり。1.0 未満なら H4 を否定
  判断: 超える → 露出・トーンマップを別要因として D5 の後に計画。超えない → H4 を台帳から外す
  次担当: PC でファイルを読める作業者（Unity 不要）
D2 料理位置のプローブ読取（変える要因なし、Editor スクリプトで読むだけ）
  入力: 皿中心・縁・パン下の座標。Unity 2022.3 の補間プローブ API（SH と遮蔽値。API 名は実行時に公式資料で確認）
  期待差: 太陽チャンネルの遮蔽値 ≈ 0 なら H1 を支持。L1/L0 が小さいなら H2 を支持
  判断: 遮蔽値が明確に > 0 → H3 を設定の読取で確認（値は試さない）
  次担当: Unity を扱える作業者（元 Codex 再開時またはユーザー指定）。ユーザー承認: 診断 Editor バッチ
D3 Review_Sun の有効/無効（変える要因: この 1 灯の enabled のみ）
  カメラ: FoodCaprese（主）＋ EntranceUpper（屋外の陽性対照）。陰性対照: 無変更を 2 回撮って全画素一致
  期待差: 卓上の差 ≈ 0 かつ屋外が変化 → 卓上に太陽の実時間寄与なし（H1 と整合）
  判断: 卓上も変化 → D4（影だけ None）へ。屋外が変化しない → 切替失敗、その回は無効
D4 （D3 で卓上が変化した時のみ）Review_Sun の影 Soft→None のみ

  既に MAT07 で Off にしても皿のくぼみは改善せず、と記録済み。新しい根拠（D1〜D3 の結果）が出るまで値の試行はしない
  D2 で方向成分が十分と出た場合に限り、「lilToon が主光源方向をどう求めているか」をローカルの lilToon 2.3.4 ソースで読む（読取のみ）
