COORD10-ART06ISO: ART06 の F19 内で見つかった微小な描画差について、次の工程の選択肢を整理(読み取りのみ。Claude cloud、2026-10-04 JST)
実装・候補制作・再描画はしていない。根拠は、元Codex の独立報告(指示役が照合済み)、03bfdaef の自作 8 入力、ART06P の部位・UV 記録、ART06 の候補だけ。
現在の採用はローカルの RI16。ART06 の色は保留のまま。

■ 前提として区別すること
- texel の不変:
  - 専用テクスチャで tile5 以外の全画素が同じこと。ART06 の検証で PASS している。
- filtered 描画の不変:
  - Bilinear、11 mips、BC7 を通したあとの表示が同じこと。
  - 今回は成り立っていない(内側の縁と境界で、最大 1〜2/255。Painting の境界 1px は最大 8)。
- 前者が成り立っても後者は保証されない。どちらの閾値も緩めない。
- 未観測の部位(背面の interior など)は PASS として扱わない。
- 今の計測は表示用 PNG だけ。GPU の tap、EXR/HDR では測っておらず、原因はまだ一つに確定していない。

■ 仮説(未確定。確定に必要な最小の確認は下記)
- F19 の slot0 は、1 枚の専用テクスチャを外枠(tile3)、内側の縁(tile4)、背面(tile1)、台紙(tile5)の全部位で共有している。
- tile4 は tile5 の左隣、tile1 は tile5 の上隣にある。tile3 は隣ではない。差が出たのは、内側の縁と背面の境界だけで、外枠の報告はない。
- 各面の UV はセルのほぼ全体を使っていて(ART06P の記録で約 0.237/0.25)、セル外周の余白は mip0 で数 px しかない。
- そのため、次の三つで、隣の tile5 の色が tile4/tile1 側の境界の texel に混ざる可能性がある。
  - 低い mip(セルが小さくなるほど余白が 1 texel 未満になる)
  - Bilinear の 4 tap
  - BC7 の 4x4 ブロック(高い mip ではセルがブロックより小さくなる)
- 大きさ 1〜2/255 が境界にだけ出ることとは整合する。
- Painting の境界 1px(最大 8)は Painting のテクスチャが変わっていないので、次の二つのどちらかが考えられるが、未確定。
  - 台紙と絵の幾何の境界で起きる画素の被覆の混色(AA)
  - mip による台紙側の混入

■ 選択肢 1: 微差を明記したうえで視覚判断し、候補を採用する(完全不変とは言わない)
- 利点: 追加の実装がない。mesh、UV、法線、slot の構成に触れない。台紙の青みが弱まる効果(資料の相対色相に近い)はすでに確認済み。
- 変更範囲: ART06 の専用材質と専用テクスチャを F19 slot0 だけに差し替える(元Codex の検証で済んでいる構成)。
- 原本の保持: 入力、共有 FinishAtlas、他の 32 texture ユーザー、RI16 は保持する。原本の texel は tile5 以外同一。
- 依存: 指示役の視覚判断。微差(内側の縁と境界で最大 1〜2/255、Painting の境界 1px 最大 8)を許容するかどうか。
- 検証: 既存の計測で足りる。採用記録には「texel は tile5 外で不変、filtered 描画は境界で微差あり、未観測の部位は未判定」と書く。
- 残る制約: 非台紙の描画は完全不変ではない。視点、距離、mip によって差の位置や大きさが変わりうる。GPU や実機の HDR 出力は未確認。

■ 選択肢 2: 台紙 12 面だけを独立した submesh/material に分ける次候補(今は実施できない。条件の具体化だけ)
- 利点:
  - slot0(外枠 1488、内側の縁 744、背面 188 面)は元の共有 FinishAtlas と材質のまま残せる。
  - 隣のセルからの混入という経路が、構造上なくなる。
  - 台紙側だけに色を持たせられる。
- 変更範囲:
  - F19 の mesh で、台紙の 12 面(shell 3)の index を新しい submesh に移し、material slot を 1 つ追加する。
  - 頂点は増やさず、重複も作らない方針。
  - 台紙用の材質は、tile5 の色を持つ専用テクスチャ(または ART06 の専用コピー)を参照する。
  - draw call は 1 増える。
- 原本の保持: 入力の FBX と原本の mesh は上書きせず、別アセットとして作る。共有 FinishAtlas は不変。
- 依存:
  - 元Codex の native import の結果(Unity 側で読み込んだ index 順、頂点の分割、tangent の生成方式、import scale、submesh の扱い)。
  - prefab/scene の参照を差し替える範囲。
  - lightmap UV(UV1)の有無と、static batching の扱い。
- 検証(すべて分割前と同じであること):
  - 頂点数、位置、法線、tangent、UV0、UV1(あれば)
  - bounds、transform、倍率
  - index の集合(submesh をまたいだ合計)
  - slot0 側が元の material と texture を参照していること
  - そのうえで、既存と同じ ROI と閾値で描画を比較する。台紙の境界(幾何 AA)の差は残りうるので、別に記録する。
- 残る制約:
  - mesh の構造(submesh 数、material 配列)が変わるので、「元のアセットと同一」ではなくなる。
  - tangent を再計算すると、法線マップがなくても差が出る可能性がある。
  - 台紙の外周の画素の被覆による混色は消えない。
  - 実施には native の検証が必要で、cloud だけでは確定できない。

■ 選択肢 3: shader や mip 設定の変更案(勧めない。短く)
- 考えられる案(いずれも専用テクスチャか材質だけに限る)は次の三つ。
  - (a) 専用テクスチャの mip 数を制限するか、mip をなくす。
  - (b) Point filter にする。
  - (c) shader でセル内の UV を clamp し、LOD を手動で指定する(tile を意識したサンプリング)。
- 勧めない理由:
  - (a) と (b) は、F19 の全部位で遠景や斜めの見え方(aliasing、シマリ)を変えてしまい、微差よりも大きな描画変化になる。
  - (c) は shader を新しく作るか改造する必要があり、BC7 のブロックによる混入は消えない。
  - global な quality や texture の設定を変えると、他の 32 ユーザーに波及する。
  - どの案も cloud では検証できない。
- 未検証: どの案も試していない。効果も副作用も推測にとどまる。

■ 原因を確定する場合に、本当に必要な最小の追加確認(どちらも読み取りのみ。再撮影はしない)
- (A) 専用テクスチャの mip ごとの比較:
  - import 済みの原本 FinishAtlas と専用コピーの全 11 mip を decode する(BC7 を展開した値)。
  - tile5 の外で差のある texel の数と位置(どのセルのどの辺か)を、mip ごとに数える。
  - 境界 texel にしか差がなく、tile4/tile1 側に限られていれば、仮説と整合する。
- (B) 既存の差分画素の位置と部位の境界の照合:
  - 撮影済みの PNG の差分画素が、台紙と隣接する部位の境界(幾何の境界)に乗っているかを照合する。
  - 既存の画像と既存の UV 記録だけで行い、新たな撮影はしない。
- これ以上(GPU capture、HDR/EXR での撮影、全 scene の調査)は、今は必要ない。

■ 翌工程の推奨順
1. 元Codex: 最小確認の (A) を行う。必要なら (B) も行う。どちらも読み取りのみ。
2. 指示役: 選択肢 1 で、微差を明記したうえで視覚判断し、ART06 の採用か保留かを決める。完全不変とは書かない。
3. 選択肢 1 で許容できず、非台紙の描画を厳密に不変にする必要がある場合だけ、選択肢 2 を次候補として、native import に基づいて検討する。
4. 選択肢 3 は行わない。
