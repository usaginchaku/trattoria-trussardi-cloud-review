COORD10-CAB04BASE  C3m の bpy4.3 無変更書き出し(baseline)の証拠 — Claude cloud 補助作業
================================================================================
目的 : 「C3m を bpy 4.3 で無変更のまま書き出しても、法線が最大 0.747° ずれる」という記録を、ローカル担当が実物どうしで追試できるようにする。
       形状の修正・新しい候補は含まない。

■ ファイル
 baseline_fbx/WallCabinet_FUR06_C3m_passthrough_bpy43.fbx  無変更書き出し(テクスチャパスはファイル名だけ)
 baseline_fbx/FinishAtlas_FUR06.png                          相対参照を成立させるための atlas(C3m と同じバイト列)
 audit_normals.json / audit_summary.csv                      SHA、頂点/面/ループ数、外寸、軸、材質、閾値 0.05° の該当数
 loop_normal_diff_table.csv                                  ループごとの角度差(12660 行:基準 vs C3m、C4 vs 基準、C4 vs C3m)
 export_import_profile.json                                  書き出し/読み込みの設定
 tools/audit_normals.py                                      FBX 内の配列を直接読む比較コード(Blender の読込処理を通さない)

■ どの FBX を使ったか
 - C4 の 0.033° 比較で実際に使った無変更 FBX は、scratchpad に残っていた(sha256 920aec82…, 169500 bytes)。
   C4 と同じ build_c4.py(md5 ed9c7312…)を identity モードで実行したもの。
   処理: 読み込み → 全辺を sharp → 読み込んだ法線をそのまま再設定 → 書き出し。
   頂点移動・法線再計算・UV 修復・材質変更はしていない。
 - この FBX にはテクスチャの絶対パス(クラウド作業場所)が入っていたので、公開版はパス文字列だけをファイル名に書き換えた(sha256 7c5c5b8e…)。
   書き換え前後で、ループ順は同一。法線の差は最大 1.2e-6°、頂点位置と UV は同一。

■ 結果(閾値 0.05°。いずれも、ループ順と頂点番号が同一であることを FBX の PolygonVertexIndex で確認してから比較)
 1) C3m 原本 vs 無変更書き出し : 最大 0.7471°、0.05° 超 251 ループ、0.5° 超もあり(audit_summary.csv)。
    UV・頂点位置・面順・材質は同一。→ bpy 4.3 の読み込み・書き出しパイプライン自体による差(ベースラインの差)。
 2) 無変更書き出し vs C4(共通の元 12660 ループ): 最大 0.0333°、0.05° 超 0。→ C4 の編集による法線の変化はない(候補の差)。
 3) C3m 原本 vs C4: 最大 0.7471°、251 ループ。1) と同じループ・同じ値の範囲 → 差はほぼすべて 1) のベースライン由来。
 外寸: 原本と基準の bbox は同一。C4 は追加頂点を含めても同じ bbox。
 材質: どれも FinishAtlas_FUR06 の 1 slot。軸と単位: GlobalSettings(UnitScaleFactor 100 ほか)は一致。

■ 注意
 - C3m 原本の FBX 自体にも、テクスチャの絶対パス文字列が残っている(COORD09 の既知事項。原本は変更していない)。
 - 原因の候補(推定): 読み込み時のカスタム法線の再エンコードと、ループ空間に対する量子化。
   0.5° を超える箇所の部位特定と、Blender 5.2.2 での同じ追試は未実施。
 - 実行環境はクラウドの pip bpy 4.3.0。Blender 5.2.2 / Unity は未実施 → 元Codex。
